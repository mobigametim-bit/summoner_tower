# Полоски здоровья поверх постаментов

16.10.2026. Исправление принято пользователем; отчёт перенесён в `docs/done/` по его указанию.

Причина: HealthBar имел z_index=0, как и изображение постамента. При таком
порядке World/Enemies и World/Slots постамент рисовался позже и перекрывал полоску.

Через Godot MCP для HealthBar в `enemy.tscn`, `orc.tscn`, `golem.tscn`, `boss.tscn`
заданы `z_index=10` и `z_as_relative=false`. Это отдельный слой над постаментами
и деталями персонажей; сам враг, движение, HP и остальные характеристики не менялись.
Настройка применяется ко всем уровням, обычному спавну и свите босса из тех же сцен.

Проверки: запуск game.tscn через MCP; в изолированном процессе созданы все четыре
типа врагов, их полоски с половиной HP намеренно совмещены с лицевой частью постаментов.
Подтверждены свойства слоя и визуальная видимость всех полосок, runtime errors отсутствуют.
Проверочные позиции и враги не сохранены в проект; прогресс изолирован через use_test_save().

Ручная проверка: встретить босса рядом с постаментом и убедиться, что полоса HP видна целиком.

Release export через MCP успешен. Обновлённая публичная сборка:
<https://mobigametim-bit.github.io/summoner_tower/?v=healthbars1>.
Снимок `318ce085f5c3bc381c2167081d11637db419c2e4` в `gh-pages`,
[развёртывание успешно](https://github.com/mobigametim-bit/summoner_tower/actions/runs/38822573507).
В публичной Web-версии выполнен короткий запуск боя с touch и призывом;
ошибок Godot/JavaScript и HTTP-запросов нет, кадр 585×1266 при CSS 390×844 / DPR3.
Проверка намеренного перекрытия всех четырёх типов выполнялась в Godot,
реальный боссовый бой на телефоне остаётся ручной проверкой.
