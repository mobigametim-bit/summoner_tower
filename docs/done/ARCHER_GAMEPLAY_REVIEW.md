## Реализация

`scenes/archer.tscn` сохраняет CombatUnit, Sprite2D Visual и Marker2D Muzzle; рядом добавлен необязательный ArcherVisual. У Mage и Frost Mage этого узла нет. Gameplay выбирает цель, ведёт cooldown и создаёт существующий PackedScene Arrow. Visual содержит только rig, анимации и палитру.

Review первоначально создавался через MCP как копия game.tscn. Перед commit переведён через Godot Editor MCP в native inherited scene от game.tscn: теперь получает актуальную структуру основной игры и не дублирует ссылки на незакоммиченные ресурсы арены. Его debug script расширяет прежний game_manager.gd, prefab и ресурсы gameplay общие. AnimatedArcher — development-вариант Archer с включённым visual.

AnimationPlayer в игровом режиме обновляется вручную из CombatUnit. При остатке cooldown меньше времени подготовки pose определяется через seek без method callbacks. В прежний кадр выстрела visual переходит на 0,24 s и выдаёт однократный release; CombatUnit вызывает прежний `_fire()` и сбрасывает cooldown как раньше. Мгновенный первый выстрел и мгновенная атака новой доступной цели при истёкшем cooldown сохранены. При Rapid Fire скорость клипа max(1, 0,52 / interval): gameplay не ждёт завершения клипа.

SpawnPlayer отдельно управляет только Root, воспроизводя исходный 0,4 s spawn. RESET атаки сохраняет эти Root-трансформации. Появление не задерживает первый выстрел. Перенос/смена режима отменяют подготовку; stop останавливает обе анимации. Пауза дерева останавливает и подготовку, и spawn.

На release NockedArrow скрывается. Настоящий Arrow использует прежнюю `assets/arrow.svg` и прежний Muzzle (32, −8), зеркалируемый вместе с unit. ReleasePoint под Bow — визуальный ориентир, не источник gameplay координат. CombatProjectile, его скорость, размер летящей стрелы, обработка цели, урон и время жизни не изменены.

Уровни меняют ткань через один простой canvas_item shader на четырёх Sprite2D: Body, Head, BowArm, DrawUpperArm. Lv1 зелёный исходный; Lv2 оранжевый, Lv3 красный, Lv4 синий, Lv5 фиолетовый. Shading сохраняется по яркости исходной заливки. Кожа, волосы, ремни, ботинки, лук и колчан не перекрашиваются. ShaderMaterial локален для unit и общий для его четырёх частей. Новых rig и текстур для уровней нет.

Drag preview получает master.svg, этот же материал и масштаб 100/256 от бойца. Static и остальные типы сохраняют прежние текстуры и масштаб. Merge, swap, возврат, экономика, ресурсы характеристик и формулы не изменены.

## Rigid cutout vs limited mesh

| Наблюдение | При игровом масштабе | Можно решить rigid | Что даст mesh |
|---|---|---|---|
| Плечо, локоть, ноги и голова | На осмотренных позах дыр не обнаружено; нужен ручной осмотр движения | Округлые overlap, pivots и слои уже работают | Подтверждённого улучшения нет |
| Короткая рисующая рука | Движение стилизовано, плечо смещается под корпусом во время натяжения | Можно уточнить форму/позицию/ключи, если пользователь увидит проблему | Потребует разметки и weights; усложнит пилот и остальные units |
| Капюшон и короткая одежда | Жёсткие формы сохраняют читаемый силуэт; длинной гибкой ткани нет | Слабое движение головы/корпуса достаточно | На текущем размере не обосновано |
| Слои руки, корпуса и лука | Удерживающая рука за корпусом; лук перед рукой | Исправлено z-order по принятой правке | На порядок слоёв deformation не влияет |

**Рекомендация: KEEP RIGID CUTOUT.** Не обнаружена проблема, для которой сначала нельзя попробовать art shape, overlap, pivot, z-order или animation keys. Mesh пока не используется. Если ручная проверка обнаружит конкретный дефект, остаёмся на текущем gate и исправляем его.

Pipeline подходит для ограниченного числа союзников: 9 костей и 9 Sprite2D плюс стрелка на unit, 9 общих Texture2D частей 256×256 (~2,25 MiB RGBA без mipmaps), один общий master для drag (~0,25 MiB), без отдельной палитры текстур на каждый уровень. Shader простой и проверен в Compatibility Web.

Для большого числа врагов риск — линейный рост bones, sprites, draw calls и прозрачного overdraw. Mesh не уменьшает автоматически количество частей и draw calls; добавляет vertices/weights, работу с deformation и дополнительные проверки соединений для каждого asset. Web performance cost нужно измерять на будущих врагах и массовом spawn, а не переносить native FPS Archer на сотни enemies. Точные дополнительные часы production и стоимость mesh ещё не измерялись. До приёмки Archer к Goblin не переходим.

## Ручная приёмка

1. В игровом preview дважды нажать башню: два Archer появляются на постаментах. Оценить размер, idle, слои и читаемость.
2. Дождаться врагов в радиусе: натяжение/выстрел читаются, стрелы летят, поза возвращается в idle; два лучника работают одновременно.
3. Перенести одного Archer на другого: Lv2 оранжевый, лицо/волосы/лук прежние. Перенести в пустой слот, проверить зеркалирование и drag preview.
4. Переключить STATIC / ANIMATED во время боя, затем вернуть Archer на башню: возврат 22 маны после первых двух призывов и merge, бой продолжается.
5. В ArtAnimationTest посмотреть attack при 0.5×, idle и spawn при 1×, Mirror и игровые масштабы: нет заметных дыр, clipping или застрявшей позы.
6. После результата Restart: новый забег начинается без старых стрел и бойцов.
