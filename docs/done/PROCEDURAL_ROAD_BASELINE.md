направления и длин прямых отрезков. Новая генерация этим документом не принимается.

## Параметры

| Параметр | Значение |
|---|---|
| `column_range` | 6–8 |
| `playable_rect` | `Rect2(0, 0, 720, 1184)` |
| `slot_count_range` | 6–10 |
| `turn_probability_range` | 0.25–0.75 |
| `route_length_range` | 1300–2500 |
| `minimum_attack_range` | 260 |
| `minimum_coverage_length` | 160 |
| `generation_attempts` | 24 |
| `search_steps_per_attempt` | 1200 |
| `cell_gap` | 4 |
| `decoration_probability` | 0.55 |

Ресурс `battlefield_config.tres` явно задаёт длину 1300–2500 и шесть текстур
окружения: rock, shrub, grass, tree, gravestone, sheep. Остальное берётся из
значений по умолчанию класса конфигурации.

Параметры GameManager: процедурное поле включено, `battlefield_seed = -1`,
`battlefield_columns = 0`, `battlefield_slot_count = 0`.
Отрицательный seed означает новый случайный seed; нулевые columns и slot_count
означают случайный выбор в заданных диапазонах. Карта сохраняется между волнами.

| Сетка | Всего клеток | Размер клетки | Диапазон числа переходов |
|---|---|---|---|
| 6×9 | 54 | 120 | 11–20 |
| 7×11 | 77 | 720/7 ≈ 102.857 | 13–24 |
| 8×13 | 104 | 90 | 15–27 |

Из диапазона переходов выбираются только значения с чётностью, соответствующей
манхэттенскому расстоянию между порталом и башней.

## Поведение исходного алгоритма

1. RNG с seed карты выбирает ширину, вероятность поворота, число слотов,
   портал в верхнем ряду, башню в нижнем ряду и целевое число переходов.
2. Каждая попытка начинается с портала. Первый переход обязательно вниз:
   движение в другие клетки верхнего ряда запрещено. В нижнем ряду допустима
   только клетка башни.
3. Поиск идёт по одной клетке в четырёх направлениях: вниз, влево, вправо, вверх.
   Запрещены выход за границы, повторное посещение и боковое соприкосновение
   с непоследовательным участком дороги.
4. Вероятность поворота определяет порядок перебора соседей. Поиск с откатами
   стремится получить точное целевое число переходов. Бюджет 1200 учитывает
   вызовы поиска, а не только клетки итогового пути.
5. После успешного пути выбираются свободные соседние клетки для постаментов.
   Кандидаты разделены на три группы по началу, середине и концу дороги;
   случайные клетки выбираются из групп по очереди. Если кандидатов мало,
   запускается следующая попытка.
6. После 24 неудачных попыток запасной алгоритм перебирает обходную колонку:
   от портала к ряду 1, по ряду 1 к этой колонке, вниз до среднего ряда,
   по среднему ряду к колонке башни и вниз к башне. Из вариантов нужной длины
   с достаточным числом слотов выбирается ближайший к целевой длине.
7. Кривая проходит через центры клеток; длина равна числу переходов × размеру
   клетки. `Curve2D.bake_interval = 4`.
8. Декор использует отдельный RNG с `seed XOR 0x5A17C3`, масштаб 0.9–1.5
   и вращение от −0.2 до 0.2 радиан; его выбор не изменяет дорогу и слоты.

Точность описания: проверка `is_valid()` проверяет минимум 160 единиц дороги
в радиусе 260 от слота. Сам `_choose_slots()` в этом сохранённом варианте
не фильтрует кандидатов по покрытию, а `generate()` не вызывает `is_valid()`.
Это параметры проверки, а не дополнительное гарантированное правило выбора.

## Порядок восстановления

Если эксперимент не принят, сравнить текущие три файла с архивом и восстановить
только относящиеся к генерации изменения. Не откатывать весь проект или HUD.
Архив сначала распаковать в отдельный временный каталог, сверить SHA-256 и пути;
учесть возможные независимые правки после даты фиксации.

После восстановления синхронизировать скрипты с Godot через MCP, проверить
импорт и короткий запуск с проверкой runtime errors. Для браузерной проверки
повторить Web export. Старые параметры сами по себе не восстанавливают
алгоритм — для этого сохранён исходный `battlefield_generator.gd`.
