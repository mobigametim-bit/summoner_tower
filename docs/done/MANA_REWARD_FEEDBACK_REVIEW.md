# Награда маны над врагом и реакция счётчика

16.10.2026. Реализовано по запросу пользователя и принято им. Отчёт перенесён в `docs/done/`.

## Для игрока

- При убийстве врага над местом его гибели появляется `+N` и существующий синий
  значок маны. Подпись немного увеличивается, поднимается и исчезает за 0.9 секунды.
- Число берётся из того же расчёта, который начисляет ману: учитываются тип/уровень
  врага и бонусы забега/меты. Отдельного расчёта наград для визуализации нет.
- Счётчик и значок маны в нижней панели коротко покачиваются при каждом изменении
  баланса: получение награды, призыв, продажа, замена бюджета при переходе карты.
  Рост сохраняет ранее существовавшую подсветку значка.
- Повторный сигнал с прежним балансом не перезапускает эффект. Первое отображение
  стартовой маны проходит спокойно. Дошедший до башни враг не показывает награду.

Баланс, сроки начисления, правила убийств и продаж не изменялись. Новых звуков нет.

## Реализация

- `scenes/ui/ManaRewardPopup.tscn` — переиспользуемая сцена с Label и TextureRect,
  существующими Tsap-Tsarap и `assets/mana_flame.svg`.
- `scripts/ui/mana_reward_popup.gd` — короткий Tween, привязанный к узлу; затем queue_free.
- `GameHud/ManaRewards` хранит временные подписи под модальными окнами и не захватывает ввод.
  Позиция смерти переводится из canvas врага в координаты HUD с учётом камеры.
  Краевые подписи сдвигаются внутрь поля для читаемости.
- В GameManager существующая рассчитанная награда передаётся в HUD рядом с add_mana.
  WaveManager и защита от повторной смерти сохранены.
- `mana_feedback.gd` вращает только визуальные элементы: контейнеры HUD не перемещаются.
  Каждый импульс отменяет предыдущий и завершается нулевым углом без накопления смещения.

Для мобильного Web нет новых частиц, шейдеров или постоянного поиска объектов.
Одновременно сохраняются не более 32 подписей; при большем количестве удаляется
самая старая. Это ограничение отображения, начисления не теряются. Сохраняются
принятые ограничения разрешения и 60 FPS. Физический телефон отдельно не измерялся.

## Проверки

- Godot MCP: сцены созданы/подключены через редактор, изменённые скрипты валидны.
- В управляемом запуске настоящего game.tscn: убийство гоблина даёт +3 и ровно одну
  соответствующую подпись; повторное take_damage не повторяет начисление/эффект.
- Отдельно проверены Lv5 Goblin (+48) и Lv3 Boss (+120) при исходных бонусах проверки;
  фактическое изменение маны совпадает с подписью.
- Призыв, ручная продажа и автопродажа меняют баланс и запускают реакцию счётчика.
  Повторный state_changed с неизменной маной не создаёт новый Tween.
- Контакт врага с башней не выдаёт ману/подпись. После эффектов поворот равен нулю.
- 50 одновременных вызовов визуализации ограничены 32 подписями; все удаляются,
  в том числе при открытом модальном окне/паузе. Скриншот +48/+120 просмотрен.
- Дополнительный сценарий у верхней границы: подпись остаётся не выше центра y=28
  до затухания и штатно удаляется, без обрезания числа при подъёме.
- Тестовый прогресс изолирован через SessionProgress.use_test_save(); обычное сохранение не менялось.
- Финальные runtime errors через MCP отсутствуют. При настройке исправлена синхронизация
  открытых скриптов редактора; начальный отладочный вызов к уже завершившейся волне заменён
  управляемым сценарием со своим врагом. Эти неудачные вызовы не входят в успешные проверки.
- Release export через MCP успешен; Edge/Chromium с touch, CSS 390×844, DPR3,
  внутренний кадр 585×1266. Проверены призыв, обычный бой нескольких волн, рост маны,
  вылетающая +3 с иконкой и открытие настроек. Скриншоты просмотрены;
  ошибок JavaScript/Godot и HTTP-запросов нет.

## Ручная проверка

1. Убить несколько врагов: над каждым должна появляться награда со значком маны.
2. Призвать и продать бойца: счётчик должен реагировать на расход и приход.
3. Проверить читаемость на телефоне и отсутствие остаточного наклона после серии убийств.

Настоящее устройство и Safari/iOS не проверены автоматически.
