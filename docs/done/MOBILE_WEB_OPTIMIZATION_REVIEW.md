# Экономное разрешение Web и звук в фоне

Принято пользователем 16.10.2026; отчёт перенесён в `docs/done/` по его указанию.

16.10.2026. Реализовано; требуется ручная проверка нагрева на устройстве пользователя.

## Изменения

- `web/loading.html` задаёт внутренний размер canvas отдельно от CSS-размера экрана:
  DPR не выше 1.5, короткая сторона не выше 720 px, длинная не выше 1280 px.
  Меньшие экраны не растягиваются до этого предела принудительно. Пропорции сохраняются,
  размер пересчитывается при resize, смене ориентации и pageshow.
- В основном preset `Web` установлен `html/canvas_resize_policy=0`: Godot использует
  назначенный размер canvas. CSS-область и координаты касаний остаются экранными.
  Это проверено по JavaScript установленного экспортного шаблона 4.7.2 и в браузере.
- `application/run/max_fps=60` ограничивает частоту отрисовки, в том числе для экранов
  90/120 Гц. Физический шаг и игровые характеристики не изменялись.
- `AudioService` через JavaScriptBridge слушает visibilitychange, blur/focus,
  pagehide/pageshow и freeze/resume. При скрытии страницы/потере фокуса обе аудиошины
  заглушаются, текущая музыка ставится на паузу, короткие эффекты останавливаются.
  Новые звуки в фоне не запускаются. После возвращения музыка возобновляется.
- Временная блокировка не переписывает настройки громкости. Нулевая громкость
  остаётся нулевой. Пользовательская пауза, настройки и модальные окна не закрываются.
  Подписки браузера удаляются при выходе AudioService из дерева.

Основной стек сохранён: Godot 4.7.2, Compatibility, однопоточный Web,
стандартные MP3-потоки. Новых зависимостей в игре нет.

## Целевые проверки

- Godot MCP: скрипт валиден, запуск main успешен, runtime errors отсутствуют.
  В изолированном процессе проверены mute/unmute, сохранение уровней громкости,
  нулевая громкость, неизменность `SceneTree.paused` и `Engine.max_fps=60`.
- Release export через MCP успешен. После экспорта выполнен `tools/package_web.py`.
- Edge/Chromium, отдельный контекст с touch и DPR3:

| CSS-экран | Внутренний кадр |
|---|---|
| 390×844 | 585×1266 |
| 844×390 | 1266×585 |
| 834×1194 | 720×1030 |
| 1400×900 | 1120×720 |

Для 390×844 DPR3 прежний кадр был 1170×2532: новая площадь в 4 раза меньше.
Это измерение количества пикселей, а не обещание четырёхкратного прироста FPS.

- Реальное переключение между вкладками: `document.hidden=true`, фактический
  Web Audio RMS становится 0; возврат восстанавливает слышимую музыку.
  Стандартная принудительная эмуляция фокуса Playwright отключалась только в
  памяти тестового инструмента; код игры и браузерные свойства не подменялись.
- Отдельно синтетически проверены события pagehide/pageshow.
- При музыке 0% переход в другую вкладку и обратно сохраняет тишину;
  содержимое аудионастроек IndexedDB не меняется от этих событий.
- Настройки меню и окно паузы остаются открытыми после возврата.
  Касания открывают/закрывают окна, запускают бой и возвращают в меню.
  Скриншоты при телефонном и планшетном размере просмотрены.
- На уменьшенном кадре повторён целевой сценарий метаулучшений: свайпы по карточкам
  в обе стороны и короткий свайп не покупают улучшение; тап покупает ровно один уровень,
  затем открывается обычный бой. Тестовый прогресс изолирован от данных пользователя.
  В этих браузерных проверках ошибок JavaScript, Godot и HTTP-запросов не обнаружено.

## Ограничения и ручная приёмка

Реальный телефон, Safari/iOS, блокировка экрана, переключение приложений и
температура устройства автоматически не проверялись. Снижение разрешения уменьшает
работу по пикселям, но не количество объектов и draw calls. Оптимизация атласов,
материалов и частиц требует отдельного профилирования, если нагрев останется.

1. На телефоне и планшете проверить чёткость текста и кнопок, призыв, перенос/слияние.
2. Сыграть 5–10 минут и сравнить нагрев/плавность с прежней версией.
3. Во время музыки сменить вкладку, свернуть браузер, заблокировать экран: звук должен исчезнуть.
4. Вернуться: музыка должна продолжиться с выбранной громкостью; отдельно проверить 0%.
5. Повторить уход/возврат с открытыми настройками и на паузе; окна должны сохраниться.
