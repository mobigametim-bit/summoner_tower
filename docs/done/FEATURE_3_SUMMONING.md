# Фича 3 — Шесть слотов и призыв

Статус: принята пользователем 05.10.2026.

## Результат для игрока

После `PLAY` поле содержит шесть пустых слотов: по три с каждой стороны дороги.
Игрок начинает со 100 маны и вызывает `Archer Lv1` кнопкой `SUMMON`.
Защитник занимает первый свободный слот и сразу начинает автоматически атаковать.
Правые Archer развёрнуты к дороге; стрелы выпускаются со стороны лука.

Цена первого призыва — 20 маны, после каждого успешного призыва она растёт на 5.
При недостатке маны или заполненном поле кнопка отключается. HUD показывает
остаток маны, следующую цену и причину блокировки (`NEED` либо `FIELD FULL`).
При Game Over призыв и бой останавливаются. `RESTART` и `MENU → PLAY`
создают свежий забег с пустыми слотами, 100 маны и ценой 20.

## Согласованные параметры и границы

| Параметр | Значение |
| --- | --- |
| Число слотов | 6 |
| Стартовая мана | 100 |
| Начальная цена | 20 |
| Увеличение цены после успеха | 5 |
| Призываемый юнит | Archer Lv1 |
| Порядок заполнения | слева, справа; сверху вниз |
| Координаты слотов | x = 180 / 540; y = 360 / 600 / 840 |

Баланс призыва хранится в `resources/balance/summon_config.tres`.
Единая формула следующей цены: `initial_cost + cost_increase * successful_summons`.
Характеристики Archer и врага сохранены с фичи 2; общие Resources в забеге
не изменяются. Заранее установленный Archer заменён призываемыми экземплярами.

На обычные 100 маны доступны три призыва: остатки `80 → 55 → 25`, следующие
цены `25 → 30 → 35`. Получение маны за убийства относится к фиче 6.
Для проверки полного поля использовались 1000 маны только в отдельном runtime;
стартовый ресурс и обычное состояние проекта этим тестом не изменены.
Drag-and-drop и merge относятся к следующим фичам.

## Структура и игровая логика

- `scenes/summon_slot.tscn`, `scripts/game/summon_slot.gd`: редактируемый слот
  с визуальным фоном, контейнером юнита и подписью пустого места.
- `scripts/game/summon_manager.gd`: состояние маны и цены, проверка условий,
  выбор первого свободного слота, создание экземпляра `scenes/archer.tscn`
  и остановка защитников. Сигнал сообщает новое состояние HUD.
- `scripts/data/summon_config.gd`: Resource с балансом и формулой цены.
- `scenes/game.tscn`: шесть экземпляров слота, SummonManager, HUD и соединения
  сигналов. Постоянная структура создавалась через Godot MCP.
- `scripts/game/game_manager.gd`: подключает призыв к бою и завершению забега.
- `scripts/ui/game_hud.gd`: отображает состояние и передаёт нажатие кнопки.

Условия призыва проверяются до изменения слотов и экономики. Мана списывается
и цена увеличивается только после успешного размещения юнита. Повторный вызов
во время добавления узла блокируется, поскольку сигналы дерева могут вызывать
обработчики до завершения операции. Отказ по мане, вместимости или Game Over
не меняет ману, цену и число существ.

Дополнительные контролируемые проверки в живом runtime через Godot MCP:

- В каждом из шести слотов ровно один отдельный Archer в нужной позиции.
- Повторный призыв из `child_entered_tree` отклонён во время первой операции;
  лишний юнит не появляется, экономика не изменяется повторно.
- Все шесть Archer одновременно выпустили по стреле в допустимую цель;
  шесть попаданий нанесли суммарно 60 урона. Для этого отдельного теста
  HP и положение врага менялись только в runtime.
- Game Over остановил всех защитников и запретил призыв, несмотря на остаток маны.
- `MENU → PLAY` после поражения с призванными Archer вернул 100 HP,
  100 маны, цену 20, пустые слоты и отсутствие старых стрел.
- Снимки пустого, частично заполненного и полного поля просмотрены через MCP.

После исправлений финальные запуски не добавили ошибок в журнал MCP.

## Ручная приёмка

1. `F5 → PLAY`: шесть пустых слотов, 100 HP, 100 маны, `SUMMON · 20 MANA`.
2. Нажать `SUMMON` три раза. Юниты появляются сверху слева, сверху справа,
   затем посередине слева. Остатки маны: 80, 55, 25; следующие цены: 25, 30, 35.
   Кнопка отключается, повторные нажатия ничего не меняют.
3. Подождать несколько врагов: Archer стреляют, враги получают урон и исчезают,
   бой продолжается. Мана за убийства на этом этапе не начисляется.
4. Запустить свежий забег и ничего не призывать: примерно через 27 s наступает
   Game Over. `RESTART` возвращает пустое поле, 100 HP, 100 маны и цену 20.
   Повторить поражение и проверить `MENU → PLAY`.
5. Для дополнительной ручной проверки всех шести слотов в свежем запущенном
   забеге выбрать `Remote → Game → SummonManager`, установить `Mana = 1000`
   в Inspector и нажать `SUMMON` шесть раз. Остаётся 805 маны, следующая цена 50,
   поле заполнено, кнопка отключена. Это только runtime: остановить запуск
   и запустить снова, чтобы вернуться к обычным 100 маны.
6. Открыть [Web-сборку](http://127.0.0.1:4175/), проверить призыв мышью
   и масштабирование окна; при наличии устройства проверить физический touch.

Команда сервера из корня проекта, если он не запущен:

```powershell
C:\Python310\python.exe -m http.server 4175 --bind 127.0.0.1 --directory build/web
```
