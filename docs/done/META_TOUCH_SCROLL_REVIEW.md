# Исправление свайпа в метаулучшениях

Принято пользователем 16.10.2026; отчёт перенесён в `docs/done/` по его указанию.

Дата: 16.10.2026. Реализовано, ожидает ручной проверки на телефоне пользователя.

## Причина и исправление

Карточка `MetaUpgradeCard` — Button с `mouse_filter = STOP`. Она останавливала передачу
касания родительскому ScrollContainer, поэтому список удавалось двигать за полосу прокрутки.

Через Godot MCP изменены две настройки существующих сцен:

- `scenes/meta_upgrade_card.tscn`: корень Button, `mouse_filter = PASS`.
- `scenes/meta_upgrades.tscn`: `Center/Stack/Scroll.scroll_deadzone = 12` логических пикселей.

Используется штатная инерционная прокрутка ScrollContainer. При начале прокрутки Godot
уведомляет дочерние кнопки и отменяет незавершённое нажатие. Короткий тап остаётся покупкой.
Дополнительные обработчики ввода или собственная система жестов не добавлялись.
Баланс, цены и сохранения не изменены.

## Проверки

- Запуск метаэкрана и inspection через Godot MCP, финальные runtime errors отсутствуют.
- В native проверке включалась эмуляция touch только в запущенном тестовом процессе,
  без сохранения этой настройки в проект. Прогресс изолирован через `use_test_save()` с пустым путём.
- Свайп вверх/вниз: scroll 0 → 399 → 0, кристаллы 5000 и уровни остались без изменений.
- Свайп внутри одной карточки на 40 px не покупает улучшение.
- Тап с дрожанием пальца 4 px: ровно одна покупка, кристаллы 5000 → 4975, здоровье башни Lv0 → Lv1.
- Колесо мыши: scroll 0 → 120, новых покупок нет.
- Успешный release export через Godot MCP; обычный Web preset исключает debug API и тестовые сцены.
- В Web Edge/Chromium 390×844, DPR3: свайпы по карточкам до конца списка и обратно,
  короткий свайп без покупки, затем один тап с покупкой и возврат в обычный бой.
  Снимки экрана просмотрены. Проверки выполнялись в отдельном браузерном контексте
  с тестовым прогрессом 5000; данные обычного браузера пользователя не затронуты.

При первом локальном прогоне вспомогательная страница для заполнения тестового IndexedDB
вызвала лишний запрос `/favicon.ico` (404). Игровые действия и проверки экономики прошли;
тестовую подготовку исправили отдельно. Это не запрос игрового HTML, задающего `index.icon.png`.

Финальный сценарий выполнен по публичной ссылке
<https://mobigametim-bit.github.io/summoner_tower/?v=metascroll1>:
свайпы вверх/вниз и внутри одной карточки не меняют прогресс, тап покупает один уровень,
затем открывается обычный бой. Ошибок браузера и HTTP-запросов нет.
Развёртывание `7baa3d6498d4a6ca9f02383b1b10189304bc4417` успешно:
[GitHub Pages deployment](https://github.com/mobigametim-bit/summoner_tower/actions/runs/38816625460).

## Ручная проверка

1. Открыть обновлённую игру на телефоне и перейти в метаулучшения.
2. Провести пальцем по самой карточке вверх и вниз; добраться до последних улучшений и вернуться.
3. Убедиться, что свайпы не покупают карточки; короткий тап при достаточном балансе покупает одну.

## Что найдено по оптимизации

Изменений производительности в рамках исправления ввода не делали.
Из последнего принятого нагрузочного отчёта: 83 врага, 52–54 FPS и 1302–1354 draw calls на ПК;
без VFX — 58–62 FPS и 1239 draw calls. Источник:
[способности врагов](ENEMY_ABILITIES_GAMEPLAY_REVIEW.md).
Эти замеры не являются новой проверкой телефона.

При текущем Web-прогоне DPR3 canvas имел размер 1170×2532 при CSS-области 390×844 —
почти 3 млн пикселей на кадр. Это в 9 раз больше площади CSS-области и кандидат для проверки
стоимости отрисовки. Наличие высокого DPR само по себе не доказывает основное узкое место.

Предлагаемый следующий этап — профиль на телефоне пользователя и сравнение одного и того же
сценария при разных внутренних разрешениях. Затем пилот атласа SVG-частей и переиспользования
одинаковых материалов у одного типа/уровня врагов, с сохранением rigid cutout и внешнего вида.
Если замеры подтвердят вклад VFX, отдельно подобрать бюджет второстепенных частиц.
План соответствует [рекомендациям Godot по draw calls, материалам и fill rate](https://docs.godotengine.org/en/stable/tutorials/performance/gpu_optimization.html).
