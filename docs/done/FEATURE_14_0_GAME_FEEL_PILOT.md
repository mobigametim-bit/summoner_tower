## Тестовая сцена

- `scenes/debug/GameFeelFlowPilot.tscn` — постоянный UI, наш GoblinVisual, три GFFPlayer и Timer.
- `scenes/debug/GameFeelPilotBurst.tscn` — 16 CPUParticles2D с собственной процедурной GradientTexture2D, срок жизни частиц 0,65 с.
- `scripts/debug/game_feel_flow_pilot.gd` — поведение тестовых кнопок, остановка и диагностический снимок.
- `resources/debug/game_feel_flow/` — три редактируемых ресурса: импульс персонажа, импульс внутреннего Control кнопки, запуск частиц.

Внешняя Node2D-обёртка масштабируется до 1,12 и обратно за 0,24 с. Сам GoblinVisual продолжает свою `walk_loop`; его собственный scale и материалы не затрагиваются. Кнопка использует отдельный внутренний Panel, уменьшаемый до 0,90 и обратно за 0,18 с; её область нажатия остаётся на месте.

Размер переключается между крупным просмотром и существующим игровым масштабом гоблина. Выбор Lv1–Lv5 использует уже принятую экипировку и палитру. Частицы масштабируются вместе с размером просмотра и рисуются поверх персонажа.

`×10` отправляет десять запросов с интервалом 0,08 с. Для каждого отдельного эффекта используется стратегия IGNORE: пока экземпляр играет, повторный запрос не добавляет ещё один экземпляр. Разные эффекты могут работать одновременно.

## Остановка и пауза

Пилот использует отдельные эффекты через GFFPlayer, а не готовые комбинации. В нём нет freeze frame, изменения time_scale, подмены ShaderMaterial или переключения боевого AnimationPlayer.

`Стоп`, смена уровня/размера, сброс и выход из сцены останавливают три GFFPlayer и Timer. Обёртки явно возвращаются к масштабу 1: стандартный GFFTween.stop() сам не восстанавливает прерванное свойство.

При входе в паузу временные эффекты отменяются, затем останавливается SceneTree. Скелетная анимация замораживается, UI остаётся доступен. После продолжения проигрывается обычная анимация; отменённые эффекты не возобновляются. Это выбранная политика пилота, учитывающая таймер очистки GFFParticles, работающий в реальном времени.

## Проверки

- Проверены правильный workspace, версия редактора, настройки renderer и отсутствие несохранённых сцен перед изменениями.
- Сцены и узлы созданы через MCP; скрипт и текстовые Resources — через apply_patch.
- При первичном импорте до регистрации autoload возникли ошибки разрешения `GameFeelFlow`. После регистрации и перезапуска редактора повторный запуск прошёл без новых ошибок; история журнала не удалялась.
- Lint проекта после создания скрипта: 0 ошибок и предупреждений.
- Мышью проверен запуск импульса: наблюдались изменённые scale обёртки и внутреннего Control при сохранённых материалах.
- Короткий сценарий проверил ограничение повторов, паузу, восстановление масштаба, очистку частиц и сброс во время активных эффектов. После завершения/сброса число узлов вернулось к 82, runtime errors отсутствовали.
- После финальной настройки частиц повторно проверен их видимый запуск.
- Обычный проект запущен через главное меню в бой; текущая сцена `scenes/game.tscn`, новых runtime errors нет.

### Web / Microsoft Edge

- Debug-экспорт пилота и release-экспорт обычной игры завершились с кодом 0; оба однопоточные, Compatibility.
- Пилот проверен через Playwright в локальном Edge: реальный mouse click, эмуляция touch без двойного действия, Lv1–Lv5, возврат масштаба, остановка, замороженная анимация на паузе, сброс и выход в меню при активном эффекте.
- Три серии ×10 не увеличили количество одновременно живущих эмиттеров выше одного. Число узлов: 82 до эффектов, максимум 83 во время частиц, 82 после очистки.

- Визуально просмотрены крупный и игровой размеры, экраны 450×800, 390×844 и 1280×720; сохраняются пропорции и доступность кнопок.
- Проверены нормальное главное меню и запуск первого боя после установки аддона.
- Browser console и pageerror: пусто.
- Артефакты в исключённой из Git папке `build/`: `gff-pilot-web-results.json`, снимки `gff-pilot-*.png`, `gff-normal-menu.png`, `gff-normal-game.png`. Временный браузерный сценарий — `.tools/check_gff_pilot_web.cjs`.

Физическое touch-устройство, GPU-частицы, стандартный Flash, готовые комбинации, эффекты камеры и производительность массовых волн в этом пилоте не проверялись. Совместимость подтверждена для используемых GFFTween и GFFParticles/CPUParticles2D; остальные эффекты проверяются перед своим внедрением.

## Экспорт и запуск

Обычный preset `Web` по-прежнему исключает debug-сцены, скрипты и Resources. Включён экспорт `addons/game_feel_flow/LICENSE`.

Добавлен отдельный неосновной preset `Web Game Feel Pilot`. Для воспроизведения браузерного превью через MCP:

1. `project.set_main_scene`: `res://scenes/debug/GameFeelFlowPilot.tscn`.
2. `export.build`: preset `Web Game Feel Pilot`, debug `true`.
3. Сразу восстановить `project.set_main_scene`: `res://scenes/main_menu.tscn`, в том числе при ошибке экспорта.

На передаче main scene уже восстановлена. Пилот доступен по [локальной ссылке](http://127.0.0.1:4175/preview/game-feel-flow-pilot/). Работает существующий HTTP-сервер на порту 4175, корень `build/web`. При необходимости запустить заново:

```powershell
python.exe -m http.server 4175 --bind 127.0.0.1 --directory build/web
```

В Godot открыть `scenes/debug/GameFeelFlowPilot.tscn` и запустить F6.

## Ручная приёмка

1. Нажать «Импульс»: гоблин увеличивается и возвращается, кнопка слегка сжимается.
2. Нажать «Частицы»: видны короткие голубые искры у нижней части персонажа.
3. Переключить Lv1–Lv5 и игровой размер: кожа сохраняет цвет, меняются одежда и экипировка; импульсы не сбивают анимацию.
4. Нажать ×10, затем «Стоп», повторить с «Пауза» и сбросом: нет зависших частиц или изменённого масштаба.
5. Во время эффекта выйти кнопкой домика: открывается обычное меню.

## Решение по пилоту

Free-версия подходит для проверенных простых эффектов. Рекомендуется продолжить с 14.1 (UI и получение маны) после ручной приёмки 14.0 и согласования следующего этапа. Использовать явные ссылки, отдельные визуальные обёртки, ограниченные повторы и обязательную очистку. Готовые комбинации и стандартную вспышку не подключать автоматически: требуется проверка остановки комбинаций и сохранения существующих материалов.
