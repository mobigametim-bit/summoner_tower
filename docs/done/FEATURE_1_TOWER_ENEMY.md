# Фича 1 — Башня и враг

Статус: принята пользователем 05.10.2026.

## Результат для игрока

После `PLAY` открывается поле с дорогой, башней и индикатором её здоровья.
Зелёный враг появляется сверху и движется вниз к башне. При достижении башни
он один раз наносит урон и исчезает. Через секунду появляется следующий враг.
После пятого попадания башня разрушается, появляется `GAME OVER`, новые враги
не появляются. Кнопка `RESTART` начинает заново, `MENU` возвращает в главное меню.

Интерфейс сохраняет английские подписи технического фундамента.
Графика — простые временные изображения для проверки механики.

## Согласованные параметры

| Параметр | Значение |
| --- | --- |
| HP башни | 100 |
| Урон одного врага | 20 |
| Скорость движения | 160 логических px/s |
| Пауза после исчезновения врага | 1 s |
| Одновременно активных врагов | 1 |
| Попаданий до поражения | 5 |

Баланс хранится в `resources/balance/first_encounter.tres` с классом
`EncounterConfig`. Значение паузы 1 s совпадает со значением по умолчанию класса
и видно в Inspector ресурса. Общий ресурс не изменяется во время забега.

Точки появления и контакта задаются `Marker2D` в сценах. При текущем расстоянии
730 px первое попадание происходит примерно через 4,6 s, поражение — через 27 s
после начала забега. Скорость умножается на `delta`.

## Реализация

- `scenes/game.tscn`: поле, точки появления, контейнер врагов, таймер,
  экземпляр башни и редактируемый HUD с окном поражения.
- `scenes/enemy.tscn` и `scripts/combat/approaching_enemy.gd`: переиспользуемый
  враг, движение и однократное событие достижения башни.
- `scenes/tower.tscn` и `scripts/combat/tower_health.gd`: здоровье, сигнал
  изменения HP, однократное разрушение и ограничение HP снизу нулём.
- `scripts/game/game_manager.gd`: состояния `RUNNING`, `GAME_OVER`, `LEAVING`,
  последовательный спавн, остановка забега и переходы между сценами.
- `scripts/ui/game_hud.gd` и `resources/ui/game_theme.tres`: отображение HP,
  кнопки и оформление. UI передаёт действия сигналами; правила урона находятся
  в игровых скриптах.
- `assets/arena.svg`, `enemy.svg`, `tower.svg`: исходная графика для `Sprite2D`.
- `tests/scenarios/feature_1_tower_enemy.json`: сохранённый сценарий Godot MCP
  для последовательного урона, удаления врагов и остановки после поражения.

Сцены и сигналы создавались через Godot MCP. Исходные UID существующей игровой
сцены сохранены. Рестарт перезагружает сцену: HP, таймер и враги создаются заново.
Новых autoload не добавлено.

## Выполненные проверки

Godot `4.7.2.stable.official.ed1daf0bf`, Compatibility renderer:

- Импорт, компиляция и lint: 4 сцены, 6 игровых скриптов, ошибок и предупреждений нет.
- Полный естественный цикл через Godot MCP: `100 → 80 → 60 → 40 → 20 → 0`.
  Между попаданиями враг удалён, после пятого попадания таймер остановлен,
  врагов нет, окно поражения видно. Дополнительное ожидание не возобновляет спавн.
- Измерено движение врага вниз по дороге, горизонтальная координата постоянна.
- Повторное разрешение события одного врага и повторный callback не удваивают урон.
- Чрезмерный урон оставляет HP равным 0; событие разрушения происходит один раз.
  Нулевой и отрицательный урон не меняют здоровье.
- Повторная команда спавна не создаёт второго активного врага.
- Нажатия `RESTART`, `MENU`, затем `PLAY` через MCP: новый забег начинается
  со 100 HP и одним врагом. Исходный Resource баланса не изменён.
- Визуально проверены поле, HUD и окно поражения в Godot.
- Финальный полный сценарий после исправлений прошёл без runtime errors.

Release Web export через Godot MCP завершился с кодом 0. Шаблоны соответствуют
редактору, `GODOT_THREADS_ENABLED = false`. Сценарии тестов исключены из экспорта
через `tests/*` в `export_presets.cfg`.

Экспортированная игра проверена по HTTP в headless Microsoft Edge через Playwright

## Ручная приёмка

1. Запустить проект через `F5`, нажать `PLAY`: видны дорога, башня, один враг
   и `TOWER HP 100 / 100`.
2. Дождаться первого попадания: HP становится 80, враг исчезает; через 1 s
   появляется следующий. Продолжить до `60`, `40`, `20`, `0`.
3. На 0 HP появляется `GAME OVER`. Подождать несколько секунд: враги больше
   не появляются, HP не меняется.
4. Нажать `RESTART`: 100 HP, окно поражения закрыто, новый враг движется вниз.
5. После следующего поражения нажать `MENU`, затем `PLAY`: снова свежий забег.
6. Повторить в браузере по `http://127.0.0.1:4175/`; изменить размер окна
   между портретным и широким, проверить читаемость HUD и доступность кнопок.

При необходимости сервер из корня проекта запускается командой:

```powershell
python.exe -m http.server 4175 --bind 127.0.0.1 --directory build/web
```

Проверка на физическом touch-устройстве ещё не выполнена; браузерная эмуляция
не заменяет её. Волны и защитники относятся к следующим фичам.

Пользователь подтвердил приёмку фичи 1. Отчёт перенесён в `docs/done/`,
ссылка в плане обновлена. Изменения фичи фиксируются отдельным commit
и отправляются в `origin` согласно согласованному правилу.
