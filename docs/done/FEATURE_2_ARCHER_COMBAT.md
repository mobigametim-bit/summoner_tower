# Фича 2 — Первый защитник и автоматическая атака

Статус: принята пользователем 05.10.2026.

## Результат для игрока

После `PLAY` слева от дороги стоит Archer. Когда враг входит в радиус,
Archer автоматически выпускает стрелы. Над врагом видна полоска HP;
три попадания убивают его. Через 1 s после убийства появляется следующий враг.
Убитый враг не повреждает башню. Достигший башни враг по-прежнему наносит 20 урона.

При текущем последовательном спавне Archer справляется со всеми обычными врагами,
поэтому в стандартном режиме башня остаётся со 100 HP. Это согласованное поведение
данного этапа; волны и усиление врагов относятся к следующим фичам.

## Согласованные параметры

| Параметр | Значение |
| --- | --- |
| HP врага | 30 |
| Урон стрелы | 10 |
| Интервал атаки | 0,6 s |
| Радиус атаки от центра Archer | 300 логических px |
| Скорость стрелы | 700 логических px/s |
| Положение Archer | (180, 600) |

Враг получает HP из `resources/balance/first_encounter.tres`.
Характеристики Archer находятся в `resources/balance/archer_lv1.tres`
с классом `ArcherStats`. Срок жизни стрелы ограничен 3 s; это значение
по умолчанию видно в Inspector ресурса. Общие Resources в бою не изменяются.

## Игровая логика и структура

- `scenes/archer.tscn`, `scripts/combat/archer.gd`: постоянный экземпляр защитника,
  точка выпуска стрелы и подпись. Поиск ближайшей живой цели внутри радиуса
  выполняется раз в 0,1 s по контейнеру врагов; дальность проверяется перед выстрелом.
- `scenes/arrow.tscn`, `scripts/combat/arrow_projectile.gd`: отдельная сцена снаряда.
  Стрела движется к текущему положению выбранной цели с учётом `delta`.
  Выпущенная стрела может долететь до цели, уже вышедшей из радиуса Archer.
  Попадание наносит урон один раз; другая цель для летящей стрелы не выбирается.
- `scenes/enemy.tscn`, `scripts/combat/approaching_enemy.gd`: HP bar и получение урона.
  Единое событие `resolved` различает `KILLED` и `REACHED_TOWER`.
  Завершённый враг больше не получает урон и не становится целью.
- `scripts/game/game_manager.gd`: продолжает последовательный спавн после любого
  из этих исходов; повреждает башню только при `REACHED_TOWER`. При Game Over
  останавливает Archer, спавн и врагов, удаляет стрелы.
- `assets/archer.svg` и `assets/arrow.svg`: простая исходная графика для Sprite2D.
- `Archer.attack_enabled`: параметр Inspector для проверки пропущенных врагов.
  В сохранённой игровой сцене включён, отдельный debug UI не добавлен.

Стрела удаляется при исчезновении или завершении цели, удалении атакующего
и окончании срока жизни. Проверяется также удаление цели из scene tree без её
освобождения. Рестарт создаёт новое состояние без старых снарядов и целей.

Сцены собирались через Godot MCP, существующие UID сохранены.
Перед началом работы уже имелась перестановка строки `run/main_scene`
в `project.godot`; это изменение сохранено, его значение не менялось.

## Ручная приёмка

1. `F5 → PLAY`: слева виден Archer, сверху появляется враг с полной полоской HP.
2. Враг в верхней части дороги ещё не обстреливается. После входа в радиус
   видны летящие стрелы и уменьшение HP; после трёх попаданий враг исчезает.
3. Подождать несколько циклов: появляются следующие враги, Archer продолжает
   стрелять, HP башни остаётся 100.
4. Во время запуска выбрать `Remote → Game → World → Archer` в Godot и отключить
   `Attack Enabled` в Inspector. Уже выпущенная стрела может завершить полёт;
   следующие враги проходят к башне, HP уменьшается, на 0 появляется Game Over.
5. Нажать `RESTART`: Archer снова включён, 100 HP, старых стрел нет.
6. Повторить отключение атаки и поражение, нажать `MENU → PLAY`: свежий бой.
7. Открыть Web-сборку по `http://127.0.0.1:4175/`, проверить бой и изменение размера окна.

Если сервер не запущен, выполнить из корня проекта:

```powershell
python.exe -m http.server 4175 --bind 127.0.0.1 --directory build/web
```

Физический touch ещё не проверен. В браузерном тесте этой фичи проверялся обычный
бой; сценарии отключения Archer и поражения проверены в Godot через MCP.

Пользователь подтвердил приёмку фичи 2. Отчёт перенесён в `docs/done/`,
ссылка в плане обновлена. Изменения фичи фиксируются отдельным commit
и отправляются в `origin` согласно согласованному правилу.
