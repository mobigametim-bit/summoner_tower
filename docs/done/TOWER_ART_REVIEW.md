## Рисунок

Вручную написан SVG по `art/references/tower.png`: короткая широкая каменная башня, крупный cyan кристалл, золотая оправа и два синих знамени. Убраны дополнительные маленькие gems, узкое окно, мелкие швы и орнаменты. Камень состоит из крупных плоскостей; дверной проём даёт тёмный фон для независимой цены призыва. Фон и тень из PNG-референса не входят в art.

Три SVG части: `base`, `crystal`, `body`. Canvas 256×256, прозрачный, без trimming. Outline #29180f / 7 px, округлые стыки. Части содержат 41 простой path суммарно. Порядок base → crystal → body: золотая оправа перед нижней частью кристалла. Master нужен для просмотра; будущий runtime использует части.

| Часть | Pivot в canvas | Слой | Будущая роль |
| --- | --- | --- | --- |
| base | 128, 128 | 0 | Неподвижное основание и вход |
| crystal | 128, 95 | 1 | Пульсация, вспышки и реакции |
| body | 128, 159.9 | 2 | Верхняя конструкция, оправа и знамёна |

Origin (128,128), нижняя линия основания y=250.1. Base продолжается под body; кристалл продолжается до y=126.9 под оправу. Pivots / offsets зафиксированы в [rig_manifest.json](../../art/source/tower/rig_manifest.json). Bone2D / Skeleton2D не нужны. Подвижные пересечения проверяются на ANIMATION gate.

Правка после замечания пользователя: первая версия занимала около89% высоты canvas и выглядела меньше старой башни. Силуэт увеличен на10% по высоте и15% по ширине одинаковым transform во всех частях; pivots обновлены в итоговых координатах. Теперь видимый рисунок занимает около97% высоты и91% ширины клетки против100% /92% у текущего static. Размер canvas, положение клетки, цена и input rect не изменены.

## Выполненные проверки

- Godot MCP: правильный проект `C:/Gamedis/summoner-tower`, Godot 4.7.2 / Compatibility; несохранённых сцен нет. Файлы обновлены через rescan.
- Master и все три части импортированы в Godot как Texture2D 256×256; MCP preview master просмотрен. Mipmaps выключены. Короткий запуск основного меню через MCP: editor/runtime errors отсутствуют; игра остановлена после проверки.
- Браузер Edge после увеличения: сборка трёх частей пиксельно совпадает с master, 0 отличающихся pixels. Alpha bounds master (11,5)–(244,253): outline не обрезан canvas. Повторена только целевая проверка рисунка, масштаба и цены; полный gameplay suite не запускался.
- Просмотрен рисунок при 100 / 140 / 180 px рядом с принятым Archer. Примерка в существующую клетку: canvas 108 / 92 / 80 логических px при 6 / 7 / 8 столбцах; на экране шириной390 — примерно58 / 50 / 43 px.
- Цена 20 / 175 / 1000 отображается поверх рисунка, не закрывая кристалл. Цвет недоступного призыва переключается. Font28 / outline5 / высота rect34 и позиция соответствуют текущей конфигурации; шрифт в HTML приблизительный. Длинная цена выходит за ширину входа, оставаясь в области клетки.
- Выбор отдельной части и показ pivot работают. На viewport390×844 ширина страницы390, горизонтального overflow нет. Ошибок JS и HTTP-загрузок нет.

Это статичная примерка, не проверка анимаций или интеграции. Точные метрики CostLabel в Godot, подвижные overlap, tap / refund / hit / destroyed, ввод и бой остаются на следующих согласованных gates. Три runtime textures256×256 — ориентировочно0.75 MiB RGBA8 без mipmaps; master не потребуется загружать в бой.

Игровой код, сцены, баланс и текущий `assets/tower.svg` не менялись в рамках ART gate. После приёмки ART отдельно созданы visual / animation review сцены — см. следующий отчёт. После полной приёмки Tower этот отчёт архивирован в docs/done.

## Ручная приёмка

1. Сравнить с референсом: силуэт, каменное основание, крупный кристалл, золотая оправа и синие знамёна.
2. Посмотреть 100 px и примеры на экране390: башня и кристалл должны оставаться узнаваемыми.
3. Изменить цену на20 / 175 / 1000 и переключить доступность призыва; оценить читаемость поверх входа.
4. Принять внешний вид либо указать правки. После приёмки — TowerVisual и пять animations: crystal_pulse / tap / refund / hit / destroyed.
