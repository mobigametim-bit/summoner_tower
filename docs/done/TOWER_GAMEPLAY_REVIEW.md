08.10.2026. **Tower полностью принят пользователем.** Выполнена интеграция TowerVisual в существующий TowerHealth, ANIMATED включён по умолчанию. Старый рисунок сохранён, STATIC доступен в review. Отчёты архивированы в docs/done. Push не выполнялся.

[Обычная игра](http://127.0.0.1:4175/) · [review в бою](http://127.0.0.1:4175/preview/tower-gameplay/) · [анимации отдельно](http://127.0.0.1:4175/preview/tower-animation/) · [план](TOWER_ART_PLAN.md).

## Что изменилось

Башня показывает crystal_pulse в покое, tap при доступном нажатии, refund после успешного возврата бойца, hit при потере здоровья и destroyed при HP=0. GameManager, SummonManager и боевые характеристики не изменены ради анимаций. Призыв, начисление возврата, урон и Game Over происходят сразу по прежним правилам.

TowerHealth хранит gameplay состояние и передаёт visual события. Связь SummonManager.unit_refunded → Tower._on_unit_refunded сохранена в scenes/game.tscn через MCP. Награда за убийство и обычное пополнение маны не вызывают refund. Приоритет destroyed → hit → refund → tap → pulse; максимум одна ожидающая реакция. Destroyed отменяет её, удерживает финальную позу и не перезапускает idle. Initialize восстанавливает цвет и позу.

CostLabel остаётся самостоятельным узлом выше рисунка, z_index=10. Нижний край обводки цифр привязан к неподвижному Base, canvas y=254. Учтены descent шрифта и толщина outline: при размере80 получены совпадающие мировые координаты нижнего края основания и цифр, y=997.375. Цена не движется с корпусом; её доступность и цвет управляются прежней экономикой. Нажатие прямо на число проходит к SummonButton.

ContactPoint, прямоугольники SummonButton / ReturnZone, клетка, дорога и экономика сохранены. Размер нового canvas равен текущему размеру клетки минус4:108 /92 /80 при6 /7 /8 столбцах. Legacy Sprite2D / assets/tower.svg остаются; STATIC / ANIMATED переключает только представление и положение цифр под соответствующий рисунок.

Параметры URL ?columns=6,7,8 задают размер только в review. ?columns=8&contact_test=1 — development fixture: два существующих Boss без изменения stats проходят последние90/180 единиц дороги, наносят настоящие50+50 урона. Read-only JS snapshot доступен только в review для браузерной проверки; debug сцены и скрипты исключаются обычным export preset.

## Выполненные проверки

- Godot MCP: проект C:/Gamedis/summoner-tower, Godot4.7.2 / Compatibility. Сцены, узлы и persistent signals изменялись через MCP. Импорт, три изменённых скрипта и native runtime — без errors / warnings.
- Native: призыв за20 создаёт одного бойца и списывает20 маны без ожидания tap. Заполнение9 фактических слотов блокирует дальнейший призыв без расхода или роста цены. Возврат бойца с paid_mana20 даёт10, с25 даёт12; во время hit начисление мгновенное, refund становится ожидающей visual реакцией. Нулевой / отрицательный урон игнорируется, повторный урон уничтоженной башне не повторяет события. Повышение maximum HP работает по прежнему правилу.
- Native: STATIC / ANIMATED, независимый CostLabel и цена1000, неизменный ContactPoint, Game Over в кадр смертельного урона, сброс HP / mana / slots / animations после настоящего restart.
- Edge Web release single-thread: мышь и настоящий touch дают ровно один призыв на действие. Нажатие на число также призывает. Mouse refund20→10 и touch refund30→15 происходят один раз без дополнительного summon. Escape и touchcancel сохраняют бойца и ману; обычное убийство врага не вызывает refund animation.
- Первый браузерный сценарий остановился на Escape: тест отправлял key press/release и mouse release без ожидания кадров. После разнесения событий по кадрам отмена прошла; игровой код не менялся. Повторён незавершённый gameplay сценарий, отдельные ранее принятые animation tests не повторялись.
- Web: пауза фиксирует animation position; реальные сетки6/7/8, портрет450×800 /390×844 и широкое окно1280×720 просмотрены. Цена расположена у края основания, башня помещается в клетку, HUD и слоты доступны.
- Web: настоящий контакт Boss даёт HP100→50 с hit, затем50→0 с destroyed. Game Over наступает до окончания0.45s клипа, повторных damage / rewards нет; финальная поза удерживается, активные враги очищены. Enter выполняет настоящий restart с HP100 / mana100 / пустыми слотами и pulse.
- JS console, page errors и HTTP errors в завершённом сценарии отсутствуют. Основная сцена и исходный export preset после временного review export восстановлены. Обычная Web сборка до финальной приёмки не заменялась.

## Performance и ограничения

Tower:3 общие textures256×256, ≈0.75 MiB RGBA8 без mipmaps,3 Sprite2D,1 AnimationPlayer,0 bones. Root не использует CanvasGroup, mesh или custom shader.

В коротком бою desktop headless Edge наблюдалось65 FPS: ANIMATED при2 врагах /57 draw calls, STATIC позже при4 врагах /69 draw calls. Количество врагов различалось, поэтому эти draw calls не являются сравнением стоимости Tower; заметного падения FPS при переключении не обнаружено. Физический телефон и поздние массовые волны этим прогоном не проверены. Полный прежний regression suite не повторялся: изменения относятся к Tower visual и его событиям, выполнены целевые проверки затронутых действий.

## Ручная финальная приёмка

1. Оценить размер новой башни, кристалл и цифру у нижнего края. Для сравнения переключить ANIMATED / STATIC; отдельно открыть ?columns=6 и ?columns=8.
2. Нажать башню / число несколько раз: tap короткий, призыв мгновенный, цена читается. Проверить отключённую башню при нехватке маны или заполненных слотах.
3. Перетащить бойца на башню: отличимый cyan refund, возврат50% реально потраченной маны. Отменить перетаскивание — боец остаётся, refund не появляется.
4. Проверить hit и разрушение в [быстром сценарии контакта](http://127.0.0.1:4175/preview/tower-gameplay/?columns=8&contact_test=1), затем restart. При необходимости использовать отдельный просмотр анимаций на0.5×.
